# Платформа Explore With Me (EWM)

EWM представляет собой распределенное приложение для организации мероприятий. Приложение позволяет размещать информацию о событиях, искать интересные мероприятия, отправлять запросы на участие, а также обмениваться мнениями в комментариях.

---

## Структура архитектуры приложения

Приложение включает следующие микросервисы:

*   **`discovery-server`** — обнаружение сервисов приложения на базе Eureka.
*   **`config-server`** — хранилище конфигурации сервисов на базе Spring Cloud Config.
*   **`gateway-server`** — распределяет входные сообщения. Ожидает внешние вызовы на порту `8080`, перенаправляет их в соответствующие сервисы.
*   **`comment-service`** — сервис для работы с пользовательскими комментариями.
*   **`event-service`** — сервис событий, включающий так же работу с категориями и подборками событий.
*   **`request-service`** — сервис заявок на посещение мероприятий.
*   **`user-service`** — сервис управления пользователями.
*   **`stats-service`** — сервис статистики просмотров событий пользователями.

Библиотека с общими данными для микросервисов:
DTO, общие типы исключений, обработчик ошибок и интерфейсы Feign-клиентов упакованы в **`interaction-api`**

## Внутренний обмен данными между микросервисами (Внутренний API)

Внутрисистемные эндпоинты предназначены исключительно для внутреннего взаимодействия микросервисов друг с другом.

### Доступные внутренние эндпоинты

#### Сервис событий (`event-service`)
*   `GET /microservice/event-service/events/event/{eventId}` — получение данных о событии по его ID.
*   `GET /microservice/event-service/events/is-exist/{eventId}` — проверка существования события по его ID.

#### Сервис заявок (`request-service`)
*   `GET /microservice/request-service/request/confirmed-requests-count` — получение количества подвержденных заявок на участии в каждом событии по списку из ID событий.
*   `GET /microservice/request-service/request/event/{eventId}` — получение данных о заявках на участие в событии по ID события.
*   `GET /microservice/request-service/request/count` — получение количества заявок по определенному событию с определенным статусом заявок.
*   `POST /microservice/request-service/request/ids` — получение данных о заявках по списку ID заявок (список передается в теле запроса).
*   `PUT /microservice/request-service/request/event` — обновление данных о заявках по списку заявок.

#### Сервис пользователей (`user-service`)
*   `GET /microservice/user-service/users/{userId}` — проверка существования пользователя по его ID.
*   `GET /microservice/user-service/users/{userId}/user` — получение данных о пользователе по его ID.
*   `POST /microservice/user-service/users/ids` — получение данных о пользователях по списку ID пользователей (список передается в теле запроса).

# Модуль комментариев

Модуль управления комментариями пользователей к событиям в сервисе EWM (Explore With Me). Позволяет создавать, редактировать, удалять комментарии и осуществлять их модерацию.


---

## Обзор

Функциональность разделена на три зоны доступа:
*   **Private API**: Доступно только автору комментария (создание, редактирование, удаление).
*   **Public API**: Доступно всем пользователям (просмотр одобренных комментариев).
*   **Admin API**: Доступно администраторам (модерация статусов, просмотр всех комментариев, принудительное удаление).

---

## Статусы комментариев

Комментарии проходят жизненный цикл, управляемый статусами (`CommentStatus`):

| Статус | Описание | Видимость в Public API |
| :--- | :--- |:----------------------:|
| `PENDING` | Ожидает модерации (статус по умолчанию при создании). |         Скрыт          |
| `APPROVED` | Одобрен администратором. |         Видим          |
| `REJECTED` | Отклонен администратором. |         Скрыт          |

## API Endpoints

### Private API
> **Базовый путь:** `/users/{userId}/events/{eventId}/comments`

| Метод | Путь | Описание                                                                                                                                                                                                                                                                  | Код ответа |
| :--- | :--- |:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------| :---: |
| `POST` | `/` | Создание нового комментария. Текст передается в теле запроса (`NewCommentDto`).                                                                                                                                                                                           | `201 Created` |
| `PATCH` | `/{commentId}` | Обновление текста комментария. Требуется передача `id`, `eventId`, `userId` в теле запроса для проверки прав. Редактирование созданного комментария допустимо в течение 24 часов с момента создания и при условии, что комментарий имеет статус `PENDING` или `APPROVED`.| `200 OK` |
| `DELETE` | `/{commentId}` | Удаление комментария автором.                                                                                                                                                                                                                                             | `204 No Content` |

### Public API
> **Базовый путь:** `/public/events/{eventId}/comments`

| Метод | Путь | Описание | Код ответа |
| :--- | :--- | :--- | :---: |
| `GET` | `/` | Получение списка **одобренных** (`APPROVED`) комментариев с пагинацией. | `200 OK` |

### Admin API
> **Базовый путь:** `/admin/comments`

| Метод    | Путь | Описание | Код ответа |
|:---------| :--- | :--- | :---: |
| `PATCH`  | `/{commentId}/status` | Изменение статуса комментария. Новый статус передается в теле запроса (`CommentStatusUpdateRequest`). | `200 OK` |
| `GET`    | `/events/{eventId}` | Получение комментариев события с возможностью фильтрации по статусу (`?status=PENDING`). | `200 OK` |
| `DELETE` | `/{commentId}` | Принудительное удаление комментария администратором. | `204 No Content` |

## Тестирование

Автоматизированные тесты находятся в файле **`Комметарии.postman_collection.json`**.

### Покрытие тестов

| №  | Тест         | Метод     | Описание                            |
|----|--------------|-----------|-------------------------------------|
| 1  | Create Comment | `POST`    | Создание, проверка статуса `PENDING`|
| 2  | Update Comment | `PATCH`   | Изменение текста, проверка `updatedAt`|
| 3  | Delete Comment | `DELETE`  | Удаление автором                    |
| 4  | Update Status | `DELETE`  | Админ меняет статус на `APPROVED`   |
| 5  | Get Approved | `GET`     | Публичная выдача (только `APPROVED`)|
| 6  | Filter by Status | `GET`     | Фильтрация по `status=PENDING`      |
